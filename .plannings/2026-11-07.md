### M10 字段级 `#align(N)`
- 语法 `#align(64) head: u64`（与结构体级 `#align` 同名，不同作用域）；存 `Entity.Variable.custom_align`（复用变量级 `@(align=N)` 的槽位）。

### M11 `#aosoa[W][N]T`
- **原计划判断错**：以为要改 codegen，其实 `[N/W]#soa[W]T` 本来就是 AoSoA（实测 384B、block stride 96、字段 0/32/64），所以只是语法糖 + 校验。

### M12 `#share(label)` + `#+analysis sharing`
- `#share(producer)` / `#share(consumer)` 标注字段的 writer（label 存 `Entity.Variable.share_label`）。
- `AnalysisFlag_Sharing = 1<<2`，并入 `AnalysisFlag_All` → **默认开**（标注即触发，避免「写了注解却静默无效」）；`#+analysis !sharing` 与 `-no-sharing-analysis` 可关。带 `#+analysis sharing` 的文件会覆盖命令行关闭（与 escape/atomic 一致）。
- 规则：只比较带标注且 label 不同的字段；同行 → error；同 label 同行 → 允许；单字段跨行 → warning。
- cache line 用 `get_layout_cache_line()`（`-layout-cache-line`），与清单/intrinsic 同源；`run.sh` 断言同一文件在 128 下必须失败。
- **没有**采用计划里的 `@(cache_line=...)` 逐结构体覆盖：Odin 的 `@(...)` 只在变量/导入声明上有通道，且 cache line 是机器属性不是类型属性。

### 踩坑
- `TYPE_KIND(...)` 宏里加字段：每个续行都必须以 `\` 结尾，单行注释要写成 `/* */ \`；写错会得到 `expected unqualified-id` 和一堆 `#include within macro arguments`。

## M13 / M14：`#offset(N)` 与 `hela-layout --waste`

用户给了最初的 Hela 提案全文，要求「参考现有改动 + 提案进一步提升」。做法：先出差距分析（`.plannings/hela/13-m13-offset-and-waste.md`，逐条 采纳/修正/拒绝 + 理由），再实现提案里最后一个真正缺的布局语法。

### M13 字段级 `#offset(N)`
- 语义：字段**绝对**起始字节 = N（`#align` 是「下一个 N 的倍数」，`#offset` 是「就在 N」）。前面的空隙由这个前缀自己声明，不需要 `_` 字段。
- 落地点只有一处：`types.cpp: type_set_offsets_of` 的 non-packed 分支，`declared_offset >= 0` 时 `curr_offset = max(curr_offset, N)`，跳过 `align_formula`。存 `Entity.Variable.custom_offset`（-1 = 未声明）。
- 校验分两段（模式与 `#split` 一致）：`check_field_offset()` 做静态检查（方言、互斥、`N % align_of(field) == 0`），`check_struct_offset_fields()` 在 offsets 算完后核对 `offsets[i] == N`，用来抓重叠（`#offset(4)` 落在前一个 u64 里 → 「previous field already ends at byte 8」）。
- 为什么要 `N % align_of(field) == 0`：结构体数组的元素基址是对齐的倍数，只要 N 也是，字段就永远对齐；否则后端会发出类型不允许的非对齐访问。这条比 `#packed` 宽松、比放任严谨。
- `#explicit` **接受** `#offset` 声明的空隙（这是唯一一处需要动的旧逻辑：`check_struct_explicit_layout` 的 gap 检查里加 `if type_field_offset_of(f) < 0`）。

### M14 `hela-layout --waste`
- 纯读清单（`padding`/`tail_padding` 早就在），按 padding 降序排行；`declared` 列标 `#split(N)`/`#explicit`，因为「声明式 padding」不是 bug。
- 汇总行的 `recoverable` 只算**未声明**类型的内部 padding（tail 是对齐取整，删不掉）。
- 顺手修 bug：`render_type` 对无字段类型（array/enum/matrix/bit_field）会把整个 payload 打印成 `<tail padding>`，AI 读到就是错的。现在按 kind 打印 `elem [count] stride` / `underlying` / `backing`。

### 判断记录（写进 13 号文档）
- 拒绝 `arena {}` 作用域语法、`par group`、有界 channel 默认、所有权标注：库能力或成本过高，进库不进语法。
- 拒绝 `#aosoa` 尾 block 部分填充：`#aosoa[8][1001]` 只能退化成 `[126]#soa[8]T`，`len` 从 1001 变 1008，静默越界。
- 拒绝 `hela ast/mir --json`：Odin 已有 `-export-semantics`，导出内部 MIR 等于把 fork 钉死后端实现。
- `@nocopy` 改做成 `#+analysis alloc`（检查 proc 内隐式分配点），排在下一步第 3。

### 踩坑
- `grep` 在本机 shell 里其实是 ripgrep 语义：`a\|b` 是字面量，不是 alternation → 一律用 Grep 工具或 `grep -E`。
- Odin 的 `if` 表达式（`x if cond else y`）在无类型上下文里推不出枚举字面量，拆成两个 `return` 更省事。
- 字符串字面量多字符 rune（`'HELA'`）不可用；用 `u32` 常量并把字节序想清楚（`'HELA'` 的 byte 0 是低字节）。
- `[^]T` 切片语法靠不住，逐个字节打印；`cast([^]u8)&v` 可以拿字节视图。

## M19：`core:hela/exec` thread-per-core / shared-nothing（继续完善）

用户说「继续完善」，按长期约定自主选 `00-plan.md` 未做项里最贴项目主张的 `core:hela/exec`，过程文档 `.plannings/hela/15-m19-exec.md`。**本轮零语言改动、零编译器改动、零 codegen 改动、golden 不刷新**——用 M3–M16 已有语法验证契约能力够用。

### 实现
- `core/hela/exec/exec.odin`：N×N SPSC 邮箱矩阵（`boxes[s][d] = msg.Mailbox`，每条通道一个生产者 s / 一个消费者 d），每 worker 独占 `mem.Arena` 切片 / `event.Loop` / `cache.Cache` / 计数器；`Runtime` 只有小共享头（counters、stopping、log ring）。`start` 一次 `make` boot buffer 再按 worker 切 arena，`wait_idle` 用显式 `expected` 投递数，`stop` join → drain log → `Worker_Stats` 快照 → 释放。
- `Worker_Stats`：`stop()` 会 `delete(rt.workers)`，控制器之后只能读 `rt.stats[i]`，否则读已释放内存（运行时报 bounds check 0..<0）。
- **`consumed` 必须在 handler 之后自增**：否则 `wait_idle` 会在某 worker 还在累加 litmus sum 时返回，checksum 随机错。
- `send` 满环 `cpu_relax` 重试不丢；`stopping` 之后拒绝发送。
- `report_failure` 按 `group_find` 名字取当前句柄（组重启后 `rt.handles[]` 故意留作陈旧句柄测试）。
- `--contract` 输出进 run.sh 第 20 步当断言：grep `owner=workers` / `owner=controller` / `0 line(s) with conflicting writers`。

- litmus：4 workers × 4 dst × 256 = 4096 投递，唯一编码值求和 + 计数校验；host ~517 µs ≈ 7.9 M msg/s（TSAN 下 ~0.63 M）。

### 两个真坑（重要）
- **编译器偏移缓存**：`Runtime` 内嵌 `[8]Worker`，而 `Worker` 含 `event.Loop` → `queue.Queue(Event)` 惰性多态实例化；`Runtime` 的 offsets 在 `Worker` 尺寸定稿前被缓存 → 清单里 `workers` 与 `group` 同偏移 16832、`size_of(Runtime)` 少算 14336 B，`build` 崩在 `llvm_backend_general.cpp:3367` 断言 `offset >= prev_offset`。修法：`workers` 改显式 `make([]Worker, n, allocator)` 切片（16 B，布局不依赖 Worker 尺寸）。**不改编译器主干**（风险 + 违背可持续合并），已写进 MEMORY.md。
- **有界 SPSC 启动死锁**：容量 64 + 每通道 256 条，所有 worker 卡在 seed 的 `send` 自旋，没人进 drain → SIGTERM。定案「声明式工作预算」：`CAPACITY=512 >= PER_PAIR=256`；credits/pump 背压明确后置。
- 其余：`-vet-tabs` 不许 tab 后接空格对齐；常量数组不能变量下标（`names := WORKER_NAMES`）；`-warnings-as-errors` 抓 release/acquire 不配对（`w.stopped` 在 join 后读 → `.Relaxed`）。

## xrep 并行归并（ADR 0011，深夜场 3）

- 起点是 M25 的负面结论：dense 下伪共享无可测收益，因为 82% 时间在**单线程 K 路归并**。
  用 `XREP_PROFILE=1` 分解证实：workers 34.5ms / merge 281.3ms / filter 21.3ms（8.39M 命中、32 列表）。
- 两个正交收益叠加：
  1. **算法**：线性扫最小游标（N·K，2.68 亿次比较）→ 最小堆（N·log K，5 层下滤），
     堆里存列表下标而非条目，比较键 `(offset, 列表下标)` 精确复刻旧的平局顺序；
  2. **并行**：按**全局 rank 精确切分**成 p 段（二分边界值 v + 按列表下标补足"等于 v"的条目），
     每段一个线程，输出直接写进最终数组的已知区间。输出与串行**逐条相同且与分区数无关**。
  3. 顺带：区间过滤从"复制+append"改成"有序区间二分 + 原地前移"，无过滤时零成本；
     输出用 `runtime.non_zero_make_slice` 省掉 134MB 置零。

  1 线程 0.38→0.13s（纯算法 2.9x）；merge 281→18ms（15.6x）；filter 21→0ms。稀疏/中密度无回归。
- 分层：`search/merge.odin` 纯算法（无线程）＋ `engine/merge.odin` 线程编排；
  线程内**零分配**（全部缓冲主线程备好，避开 Tracking_Allocator 多线程 SIGBUS 老账）。
