一段 .hel 示例，配合上面的显式布局与断言：

hela
#+dialect hela
#+analysis escape !atomic sharing cacheline

@(layout = .Explicit)          // 每个字节都要显式声明，隐式 padding 直接报错
Ring_Header :: struct #align(64) {
    head: atomic_u32 @(offset = 0,  share = .Atomic(.Relaxed)),
    _:    [60]u8     @(offset = 4),                          // 显式补齐
    tail: atomic_u32 @(offset = 64, share = .Atomic(.Release)),
    _:    [60]u8     @(offset = 68),
}
#assert(layout_of(Ring_Header).size == 128)
#assert(layout_of(Ring_Header).padding == 120)
#assert(layout_of(Ring_Header).cache_line_of("head") != layout_of(Ring_Header).cache_line_of("tail"))

C 库：分三档处理，别一律"移植"

Odin 的 foreign import 原生支持 C ABI，所以先想清楚是要用、要学，还是只借鉴：

  • 绑定即可（别移植，太胖）​：hwloc / libnuma（拓扑与亲和）、mimalloc / jemalloc / snmalloc（分配器对比）、DPDK / libxdp（内核旁路）、LMDB（mmap 零拷贝 B+tree）、liburcu、HdrHistogram。⚠️ liburing 不需要——core/sys/linux/uring/ 已是裸 syscall 级封装。
  • 值得逐行移植成 .hel（算法小、教学价值高、自带对照测试）​：Concurrency Kit（BSD/C99，ck_ring、ck_epoch、ck_hp、ck_hs、ck_spinlock_mcs/hclh、ck_barrier，其 regressions/ 可直接当 Hela 版回归测试）、Vyukov MPMC bounded queue、Michael–Scott 无锁队列、Treiber 栈、flatcc（纯 C 的 FlatBuffers）。
  • 只借鉴架构，不引入：Seastar / Glommio（thread-per-core + shared-nothing）、LMAX Disruptor（SPSC ring）、simdjson（布局驱动解析）、Folly/Abseil（体积过大）、libuv/libevent（core:nbio 更强）、zlib/LZ4/xxHash（已有 vendor:zlib、core:compress/lz4、core:hash/xxhash）。

工程落地：最容易踩的坑

不要重命名整仓为 .hel。​ src/ 里 .odin 字面量有 54 处，功能性闸门在 parser.cpp:6406/6559/7797、main.cpp:4558、build_settings.cpp:2444；此外还有 1000+ 个 .odin 文件、foo_linux.odin 平台后缀筛选、CI 与 .gitattributes。推荐做法是编译器同时接受两种扩展名，用文件级 #+dialect hela 门控新特性，core/ 与 base/ 保持 .odin——这样每月合并上游 dev-YYYY-MM 几乎零冲突，这是长期能否活下去的关键。

第一个里程碑只需 4 处改动：src/main.cpp 加 -emit-layout → 新增 src/layout_writer.cpp（复用 sw_*，遍历 type_info_types_hash_map）→ hel/layout/layout.odin（字节图 + diff）→ tests/layout/*.hel 用 #assert 锁死布局。跑通后 AI 就有完整的「写 → 编译 → 读清单 → 断言 → 回归」闭环。

其余注意：#soa 的 offset 是分量数组语义而非元素语义，可视化要单独处理；布局 JSON 必须确定性排序并带 layout_hash，否则喂给 AI 的是噪声；#aosoa 是唯一会动到 check_type.cpp / LLVM 寻址的改动，放最后；别把 Rust 式生命周期搬进来，与隐式 context + 手动分配冲突，且会让 fork 维护成本失控；只靠布局不保证并发正确，必须配 hel:verify 与 TSAN，否则 AI 会稳定生成「对齐完美但内存序错误」的代码。

一句话概括：Hela 值得做的不是更多语法，而是让编译器成为布局的唯一真源，让 AI 读清单而不是猜代码。我已把这份基线调研与工程约定记入 /opt/repos/hela/.workbuddy/memory/MEMORY.md 和当日日志，方便后续接着推进。
