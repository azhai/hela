# M20：真实 IO 事件源 —— 把 `event.Loop` 接到内核

> M15–M18 补了并发契约与无隐藏分配，M19 用它们搭出了 thread-per-core 的 `exec`。
> 但直到 M19 为止，`event.Loop` 里的事件全是**人造的**：用户 `post`、注入时钟产生的 timer。
> 15 号文档「明确不做」里写得很清楚：`io_uring` / `kqueue` / IOCP backend 是缺口。
> 这一轮就补它，结论仍然反直觉：**语言一个字没改，也没再写一个 reactor。**

## 0. 起点：之前为什么不做，现在为什么能做

14 号文档拒绝 tina 的平台 IO backend，理由是「4 份 50–67 KB 平台 IO backend，平台分叉重，
且布局不可见」。这个判断到现在也没错——**错的会是自己再写一份 kqueue/epoll/IOCP**。

翻上游发现 Odin 已经把 syscall 封装好了：

| 上游包 | 内容 |
|---|---|
| `core:sys/kqueue` | `kqueue()` / `kevent()` / `KEvent`，Darwin + 3 个 BSD |
| `core:sys/posix/poll` | `poll()` / `pollfd` / `Poll_Event`，Darwin + Linux + BSD |
| `core:sys/posix/unistd` | `pipe` / `read` / `write` / `close` |

于是「接内核」不再等于「把 fork 钉死在平台 ABI 上」。Hela 侧只做三件本来就该由布局方言做的事：
把原生事件**规范化成一种固定字节形状**、把它**发布进确定性事件循环**、**声明谁拥有 poller**。
平台分叉被压缩成 2 个各约 100 行的后端文件 + 1 个 stub，且换后端时上层一行不动。

**没有用 `core:nbio`**：那是「提交异步操作 → 内核完成 → 回调」的完成模型，且是 thread-local 的全局
loop、内部带 operation pool 分配。Hela 这一轮要的是「fd 就绪 → 自己去读」的就绪模型，以及
「每个 worker 独占一个 poller 描述符」这个能写进清单的事实。完成模型是后续另一条路，不是本轮。

## 1. 语言改造：零（第二次）

M3–M16 的语法全部够用，本轮没有新增语法、没有改编译器、没有改 codegen、没有刷新 ABI golden：

| 已有能力 | 本轮用在哪 |
|---|---|
| `#+dialect hela` | 4 个新库/测试文件 |
| `#explicit` + `#offset(N)` | `Completion` 的 32 B wire format，逐字节命名 |
| `#assert` + `intrinsics.layout_padding_of/cache_lines_of` | 编译期锁住偏移、无 padding、单行 |
| `#align(64)` + `#atomic` + `#share(owner)` | `Source` 的「一个 owner、一条行」契约 |
| `#+analysis alloc` / `sharing` | `io.odin` 与 `exec.odin` 门控 |
| 清单 v5 + `--contract` | 导出 poller 归属，`run.sh` 直接 grep 当断言 |
| `-emit-layout` | 导出 `Completion`，AI 不必知道 `struct kevent` 长什么样 |

唯一改的是**库内部**一个字段：`event.Loop` 增加 `user: rawptr`，让 handler 能拿到自己的 worker，
而不必用全局变量或指针反推。`Loop` 其余字段顺序不变；`io_handler` 因此能成为 `Config` 的回调，
`exec` 保持通用。

## 2. 链路：OS 事件不再绕过确定性分派

```
   pipe / socket (real fd)
        │  write() from another thread
        ▼
   kernel readiness queue
        │  kevent(kq, ..., &ts)   [Darwin/BSD]   poll(...)   [Linux]
        ▼
   _backend_wait: KEvent / pollfd  ──规范化──►  Completion (32 B, #explicit)
        │
        ▼
   io.poll: completion_to_event() ──► event.post()   ← 只发布，不调用户代码
        │
        ▼
   event.loop_tick()  ──► loop_handler  ──► cfg.io_handler(w, c)
        │                                      │
        │                                      └─ exec.send() ──► SPSC ring ──► handler()
        ▼
   同一个 handler 顺序：same posts + same clock + same completions = same calls
```

关键不变量：**`io.poll` 绝不调用用户 handler**。`tests/hela/io` 显式断言
「`poll` 返回后、`loop_tick` 之前 `g_handled == 0`」。就是这一条让「真实 I/O」和 M17 的 DST
（确定性模拟测试）能共存：把时钟换回注入式、`Completion` 换成手工 `post`，整个分派顺序可复现。

在 `exec` 里这条链路被推到底：seed 不再凭空造消息，只为每个 worker 注册自己的 pipe 读端；
控制器写 4 个 8 B 触发值，之后 **4096 条 envelope 全部由真实内核 completion 驱动**：

```
   controller ──write──► pipe[i] ──kqueue[i]──► worker i 的 event.Loop
        └─ io_handler 发 4×256 条 ──► N×N SPSC ──► 其他 worker 的 handler (litmus sum)
```

`io_completions` 进 `Worker_Stats` 快照，测试断言每个 worker 都真的收到过内核事件，而不是靠
「没崩」推断。测试还用 5 秒有界等待替代无限 `wait_idle`：I/O 源坏了会 fail，不会挂死 CI。

## 3. `Completion`：OS 事件的固定 wire format

```odin
Completion :: struct #explicit {
    #offset(0)  kind:   Kind,  // Read/Write/Timer/User/Error
    #offset(1)  flags:  u8,    // FLAG_EOF/ERROR/HUP/EDGE
    #offset(2)  tag:    u16,   // 调用方相关性，经内核原样透传
    #offset(4)  handle: u32,   // fd
    #offset(8)  bytes:  i64,   // kqueue: 可读字节数；poll: 0（不猜）
    #offset(16) udata:  u64,   // 内核透传
    #offset(24) errno:  i32,
    #offset(28) seq:    u32,   // 采集序号
}
#assert(size_of(Completion) == 32)
#assert(intrinsics.layout_padding_of(Completion) == 0)
```

`event.Event` 只有 5 个字段，不为其改形状（改了会波及 M17 全部库）。因此
`Completion -> Event` 是**明确有损的投影**：

| Event 字段 | 承载 |
|---|---|
| `kind` | `EVENT_IO = 2`（`event` 只占 0/1，kind 是开放命名空间） |
| `tag` | `tag` |
| `id` | `udata` |
| `arg0` | `bytes` |
| `arg1` | 打包 `handle(32) \| kind(8) \| flags(8) \| errno(16)` |

`seq` 不投影：它是「采集」的属性而非「通知」的属性，`Source.completions` 已经给出全局序号。
`event_to_completion` 是其余字段的精确逆变换。**把这个损失明写出来**比假装无损更符合项目主张——
AI 读清单就知道完整记录要回 `Source.batch` 取。

## 4. 平台后端：两个真后端 + 一个诚实的 stub

| 文件 | 目标 | 后端 | `bytes` |
|---|---|---|---|
| `backend_kqueue.odin` | darwin / freebsd / netbsd / openbsd | `core:sys/kqueue` | `KEvent.data`，真实可读字节数 |
| `backend_poll.odin` | linux | `core:sys/posix/poll` | 0，`poll()` 不提供，不猜 |
| `backend_stub.odin` | windows / wasm / others | 无 | — |
| `posix_common.odin` | 上述 POSIX | `pipe/read/write/close/errno` | — |

`FULLY_SUPPORTED` 在 POSIX 为 `true`、stub 为 `false`；`source_init` 在 stub 上**返回 false**，
不是静默 no-op。`exec.start` 对此降级：没有后端时 `io.poll` 立即返回 0，纯消息链路仍可用，
不会因为「这个平台还没接 IOCP」就整个 runtime 不可用。

四个 target 都交叉 `check` 过：`darwin_arm64`（host）、`linux_amd64`、`windows_amd64`、
`freebsd_amd64`。Linux 的 `poll()` 是 O(n) 扫描，不是高性能路径；epoll / io_uring / IOCP 是
**换掉一个后端文件**的事，`Completion` 与 `event.Loop` 都不用动。

## 5. 三个真坑

### 5.1 加一个回调字段，`#assert` 立刻红了 ★

`Config.io_handler` 让 `Config` 从 56 B 变成 64 B，原本挤在 line 0 末尾的 `Runtime.expected`
被顶到 line 1，连带 `sent` / `stopping` 全部下移一行：

```
Compile time assertion: offset_of_by_string(Runtime, "sent") == Cache_Line
Compile time assertion: offset_of_by_string(Runtime, "stopping") == 2 * Cache_Line
```

**没有放宽断言**，而是把 `expected` 移到 line 2 与 `stopping` 同住：它本来就是 controller 写一次、
worker 只读的常量，放在 worker 写的 `sent` 那行反而是伪共享。断言恢复原值，契约更正确。
这是 M3 以来「编译器是布局唯一真源 + `#assert` 锁契约」第一次在真实改动里主动拦下一处布局漂移，
比任何文档说明都有说服力。

### 5.2 `seq` 不该从反解结果里读

第一版测试断言 `g_last.seq` 递增，直接失败：`event_to_completion` 按设计把 `seq` 置 0。
改成从 `Source.batch[0].seq` 读完整记录，并额外断言 `g_last.seq == 0`，把这个设计决定变成
可执行文档。

### 5.3 `poll()` 的 EOF / 字节数语义不同

- kqueue 的 `EV_EOF` 有独立标志位，`poll()` 只有 `POLLHUP`；后者同时置 `FLAG_HUP | FLAG_EOF`。
- `KEvent.data` 给出可读字节数，`poll()` 不给；`Completion.bytes = 0` 表示「就绪但长度未知」，
  而不是「0 字节可读」。测试因此只在 host（kqueue）断言 `bytes == 8`，全链路测试不依赖它。
- `posix.timespec` 的字段是强类型（`time_t` / `i64`），整数字面量必须显式 cast。
- Odin 的交叉 target 名用下划线（`linux_amd64`），不是 `linux-amd64`。

## 7. 明确不做

- 不自己声明 syscall / 不复制 `struct kevent` ABI：上游已有绑定，重复等于把 fork 钉死。
- 不用 `core:nbio` 的完成模型：本轮是就绪模型；完成模型（io_uring CQE / IOCP）是后续另一条路。
- 不改 `event.Event` 的形状：`Completion` 是新增的 wire format，Event 保持稳定。
- 不做 epoll / io_uring / IOCP：Linux 用真·`poll()` 先把语义链路跑通，高性能后端是换一个文件。
- 不做「就绪即自动 read/write」：I/O 动作属于 `io_handler`，编译器不该藏一次系统调用。
- 不做 socket / TCP / TLS 协议栈：本轮只到「真实 fd + 就绪通知」，pipe 足以证明链路。
- 跨 target golden、`#share` 跨类型、credits/pump 背压、`#view`：继续留在 `00-plan.md`。

## 8. 取舍记录

- **「真实」的验收是真的走内核**：测试用 `pipe()` + `kevent()`，不是 mock 的 completion。
- **确定性优先于便利**：IO 完成不直接回调用户代码，而是排进 `event.Loop`。这牺牲了一点直白，
  换来「同一批 post + 同一时钟 + 同一批内核事件 = 同一 handler 顺序」这条对 AI 可推理的性质。
- **平台能力要诚实**：`FULLY_SUPPORTED`、stub 返回 false、`bytes = 0` 表示未知，都不假装跨平台
  已经齐活。
- **清单仍是交付物**：run.sh 第 20/21 步直接 grep `--contract` 的 owner 行与冲突数。
